## Architecture

- Expo 57, React Native 0.86, React 19 and TypeScript; Expo Router routes in app/, domain/UI modules in src/features/, data in src/data/. Android preview runtime: 0.2.13.
- app/_layout.tsx composes auth, workspace, onboarding, Focus, Review, reminders, cloud sync, achievements and optional local-AI providers.
- Core loop: Today → Focus → Review → Progress; Plan → Start → Focus → Retrieve → Feedback → Adapt.
- Local-first, owner-scoped workspace/session storage with Firebase auth and cloud-sync modules. WorkspaceProvider is the mutation/persistence boundary: readWorkspace(expectedOwner), guarded updateWorkspace(change, {ownerKey, canApply}), waitForSaves(), and retrySaves(expectedOwner). Retry persists the latest snapshot without repeating a mutation. Preserve live-owner/revision and post-await guards.
- Deterministic planning/capacity and review-memory engines remain authoritative. Review estimates are FSRS-inspired, not individually calibrated measurements. Mistakes use spaced retest rules; progress requires recorded evidence.
- Optional assistant uses validated typed actions/proposals, existing domain APIs and provider boundaries. LiteRT-LM/model tooling and isolated hosted Worker/D1 foundations exist; that does not establish model quality, active hosting or reliable phone inference. Normal study flows work without AI.

## Codex / Gemini 4 Argon synchronization protocol

1. **Roles:** Gemini 4 Argon is the primary feature developer and code author. Codex (Astra in transferred packages) handles GitHub integration, verification, debugging, testing and explicitly authorized publishing. Work passes through the user; GitHub source outranks uploaded snapshots and assistant memory. Historical Argos reviews below retain their original attribution.
2. **Before editing:** fetch the actual active-branch head/open PRs, inspect local work and applicable instructions, and read this handoff/master checklist. Reconcile overlapping work; never force-push over another contributor or use README-only main as the application source.
3. **Source requests:** retrieve the exact latest requested files from the active GitHub branch, pinned to one verified commit. Transfer complete contents, original paths, base SHA and file hashes. Keep exports scoped; add dependencies only when requested or needed for the bounded change. Recheck the head on return rather than assuming the transfer snapshot is still current.
4. **Implementation intake:** record Argon's base SHA, affected files, rationale and acceptance tests. Compare the patch and relevant dependencies with current source before applying. A docs-only descendant does not invalidate unchanged code, but verify that explicitly. Status is needs validation / accepted / deferred / rejected / implemented; a supplied patch and its expected test results are not verified work.
5. **Integration:** handle one bounded chunk at a time. Apply safely, preserve Argon's design where practical, and resolve routine conflicts using engineering judgment. Preserve existing engines, data, tutorial/accessibility/reduced-motion behavior, owner guards and native/runtime compatibility. Return concrete failing cases and constraints to Argon when significant redesign is needed. Use a focused branch/PR when overlap or separate review warrants it; otherwise use the established branch with a leased update.
6. **Verification/save:** run TypeScript, relevant regression suites and compatibility checks appropriate to the change; inspect the final diff. Recheck remote head, reject mismatched leases, commit only verified changes and verify final content/ref. Report the exact SHA and any PR. Do not blindly apply code or claim expected/historical tests as freshly passed.
7. **Publishing:** require explicit user authorization for the particular update. A patch, source transfer, verified commit or general continuation does not authorize publication. Distinguish committed, tested, merged and published; claim publication only with an actual receipt.
8. **Handoff/report:** maintain this summary and the existing master checklist. After each completed integration provide a **GEMINI/ARGON SYNC REPORT** with reasons, exact files, branch/SHA/PR, architecture/API changes, tests/results, remaining problems and research/review questions. Documentation-only commits do not imply another app test run. Stop after the bounded chunk.
