# MYELIN functional audit — 2026-10-30

This is an audit of the repository at commit `e2a2e5eceb37e1d5e958cd06535071ce0a390408`. It describes implementation and prior automated checks, not physical-device results. Code that was being developed after that commit was lost when the build workspace reset and is not included in this version.

## Highest-priority findings

1. **Scheduled app blocking is not guaranteed to start unattended.** `FocusShieldScheduleReceiver` uses an inexact alarm, and an alarm received when the app is in the background posts a notification asking the user to open MYELIN. Force-stop, denied notifications, device power management, and Android background restrictions can prevent or delay activation. The setup should make this explicit; test the actual behavior on the user's phone before promising an automatic schedule.
2. **Website filtering uses Android's VPN slot.** The 0.2.18 code makes the filter opt-in for new settings and tries to fail open when DNS fails, but a user's existing enabled configuration is preserved and the feature can still conflict with networking, other VPNs, Private DNS, Secure DNS, or caches. App blocking is separate. A browser accessibility approach may avoid routing traffic, but it needs explicit disclosure and permission, supports only tested browsers, and must not be described as complete website blocking.
3. **Google sign-in is not yet verified on the user's device.** The local signing fingerprint documented in `native-focus-shield-google-signin.md` does not match the Android OAuth fingerprint in the checked-in configuration. Confirm the live Firebase registration and Google provider; then test the actual installed build. The mismatch is a plausible cause, not proof of the failure.
4. **Long projects lack a dedicated multi-day workflow.** Individual tasks, dates, estimates and Today planning exist, but a user cannot enter one project and distribute named parts across several days in a single flow. Add per-part dates, durations and editing without replacing existing tasks; verify how overdue and postponed parts appear.
5. **Setup does not yet guide a new or existing user through their first complete plan.** Make entering a first task, a deadline, available time and the next action easier, while allowing skips and preserving existing data. Use actual upcoming dates to communicate urgency; avoid creating artificial deadlines.

## Other beneficial checks and improvements

- Test the blocked-app screen on the phone, including large text, keyboard, navigation, break passes and the emergency exit. Keep Phone, emergency calls, Home and essential system controls accessible. Browser-based layout checks cannot verify an Android overlay.
- Test Focus start, pause, break, resume, finish, expiration and process recovery alongside blocking; check that revoking each permission does not stop the timer or leave the phone trapped.
- Verify data remains intact after an in-place APK update, app restart, account change, export/import and cloud sync conflict. Never require uninstalling before a backup.
- Test reminders with notifications allowed and denied, after reboot, in battery saver and at schedule boundaries. Android timing and manufacturer-specific restrictions can affect delivery.
- Treat assistant tests that use mocks as checks of routing and presentation, not proof that an on-device model has been downloaded or runs acceptably on the phone.
- Use a local Expo development build and Metro for fast UI iteration. Native changes still need a build; see `docs/LOCAL_ANDROID_DEVELOPMENT.md`.

## Verification boundary

The earlier workspace ran a broad set of TypeScript suites and web layout checks on a subsequent, now-lost worktree. Those results cannot be attributed to the restored code or to an APK. The newer Android build was interrupted by a workspace reset.

After restoration, genuine `tsc --noEmit` and Expo Android prebuild passed. Sixty-two existing TypeScript verification scripts ran; 60 passed initially and two stale test fixtures were corrected and passed on rerun. The recreated project-parts data test checks validation, workspace round-tripping and Today eligibility. These tests do not establish device behavior, Google sign-in, native blocking or a successful APK build.
