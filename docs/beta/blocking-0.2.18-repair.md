# Blocking screen and DNS reliability repair (Android 0.2.18)

The native blocker screen now shows one clear return action, a restrained app/status card and an optional reminder; break passes, parked thoughts, PIN/emergency access and the existing routing remain available. The setup title and tabs scroll with the rest of the content. Website filtering is off by default for new settings; existing explicit on/off choices are preserved.

The local DNS VPN now refuses to start when Private DNS is active or no underlying resolver exists. It limits the total upstream DNS attempt to 2.5 seconds. If a query still cannot be resolved, it records a failure for that enforcement window and stops the VPN so ordinary browsing can recover. A periodic native sync cannot restart the failed window. The user can tap Retry website filter after changing network settings. The app monitor is a separate service and remains available. Android still permits only one VPN, and browser Secure DNS can bypass DNS filtering.

Native changes require app/runtime 0.2.18, Android version code 15. The earlier 0.2.17 APK cannot receive this code through Expo Updates (that local test build has Updates disabled). No new APK or Expo publication is claimed here.

Verification: genuine TypeScript `tsc --noEmit`; Focus Shield A and B+C, blocking screen/settings and release checks pass. Expo Android prebuild passes with generated files matching the plugin inputs. The six affected Android core/service/UI source files compile directly with Kotlin 2.3.0 against Android API 36, with deprecation warnings only. The native DNS JVM packet suite passes. The screen renders and interactions pass in Chromium at 320/390/720 pixels, including a check that the title and tabs scroll out of view. Full Gradle assembly is blocked in this workspace because the Gradle 9.3.1 distribution cannot be reached; the React Native module and final APK have not been compiled here. Physical phone DNS, Private DNS/OEM and overlay behavior is untested.

To test after a new native build: keep app blocking enabled and website filtering off, then verify a chosen app is blocked and internet works. Enable website filtering, grant VPN permission and try allowed and blocked sites in the browser. With Private DNS active and when switching Wi-Fi/mobile or going offline, verify allowed browsing recovers and MYELIN reports a paused website filter. Retry explicitly after restoring network DNS. Check break pass, emergency override, Back, TalkBack, large text and scrolling on the blocker screen. Calls, Home, Settings and other essential system functions must stay available.
